# P4 设计 · 卡片生命周期

日期：2026-10-23
上游：`GOAL.md`（D1 格式、D6 导入导出、D7 客户端不可弄坏、D8 桌面同源）
前置：P3 已完成（设置页编辑器、实时预览、显式重新应用）

---

## 1. 目标

**在设置页里完成一张卡的完整生命周期：导入、导出、复制、删除。**

### 验收

1. 导出一张卡得到 `<id>.dshcd`；删除后重新导入，结构与未知字段完全一致
2. 导入的 id 与现有卡冲突时自动改名，不覆盖任何现有卡
3. 复制一张卡得到 `<id>-copy`（必要时继续加后缀），字段与未知字段全部保留
4. 删除一张正在被会话使用的卡后，这些会话变为「不使用角色卡」，live session 当场解绑
5. 删除默认卡后，默认指针清空，列表显示「未设置」
6. 以上操作失败时都有可见提示，且不破坏客户端 UI

---

## 2. 范围

**做**

- 单卡导入 / 导出（`.dshcd`，JSON）
- 单卡复制
- 单卡删除（含引用清理与 live 解绑）

## 4. 宿主

### 4.1 存储函数（`src/cards.js`）

1. `deleteCardFile(dir, id)`
   - 删除 `<id>.dshcd`。
   - 返回 `{ ok: true }` 或 `{ ok: false, code: 'not-found' | 'delete-failed', error }`。
2. `clearDefaultCardId(dir)`
   - 删除默认指针文件。
   - 文件不存在视为成功。
3. `detachOverridesForCard(dir, cardId, logger)`
   - 读取覆盖表，把所有值等于 `cardId` 的项改成 `null`（显式「不使用」）。
   - 一次写回；返回受影响的会话数。
   - 其他项（包括本来为 `null` 的项）保持不变。

### 4.2 `DELETE /dsh-character-cards/cards/<id>`

在现有 `/cards` 前缀路由内增加 `DELETE` 分支。顺序固定，避免出现「文件已删、引用还在」的中间状态：

1. 校验 id；无效 → 400。
2. 卡不存在 → 404。
3. 记录 `affected = sessionsUsing(ctx, id)`，这是删除前解析到该卡的 live 会话。
4. `deleteCardFile`；失败 → 500，后续步骤全部不执行。
5. `detachOverridesForCard`。
6. 若默认指针等于该 id，调用 `clearDefaultCardId`。
7. 对 `affected` 中仍存在的 live agent 调用 `rebind(agent, sessionId, logger)`。
   - 覆盖表已是 `null`，解析结果为「无卡」，`registerSection` 同步移除旧 section。
8. 返回 `{ ok: true, id, detached, rebound, warnings }`。

删除文件是提交点。第 5、6 步任一失败不回滚已删除的文件，而是记入 `warnings` 并
继续执行第 7 步；响应仍是 200，客户端提示「卡片已删除，但引用清理未完全成功」。
这样调用方不会误以为卡片还在，同时清理问题可见。

### 4.3 删除语义

- 被钉在该卡的会话：覆盖表写 `null`，明确「不使用」。
- 跟随默认且默认就是该卡的会话：默认指针清空，当前同样无卡；以后设置新默认时会重新跟随。
- 非 live 会话：覆盖表与默认指针已持久化清理，下次启动生效。
- 删除失败时不改任何引用，也不解绑。

## 5. 客户端

### 5.1 入口

- 「默认角色卡」卡片的 `新建卡片` 左侧新增 `导入`（outline），触发隐藏的
  `<input type="file" accept=".dshcd,application/json">`。
- 每行末尾新增 `更多` 菜单：`编辑 / 导出 / 复制 / 删除`。
  卡片名称仍是直接进入编辑器的按钮。
- `重新应用` 保持只在 `sessionsUsing > 0` 的行上显示，与生命周期操作分离。
- 删除采用行内二次确认：选择「删除」后该行出现 `确认删除？`，再给 `确认 / 取消`。
  不使用模态框。

### 5.2 纯函数

1. `uniqueCardId(base, ids)`
   - `base` 空闲则直接返回。
   - 否则依次尝试 `base-2`、`base-3`……
   - 后缀拼接前截断 `base`，保证结果不超过 64 字符。
2. `prepareImport(card, ids)`
   - `structuredClone` 原对象，只替换 `id`。
   - id 先清洗：转小写，非法字符折叠为 `-`，去掉首尾 `-`，截断到 64。
   - 清洗后为空则回退为 `imported-card`。
   - 返回 `{ card, renamed, versionWarning }`；`versionWarning` 在 `dshcd !== 1`
     （包括缺失）时为 true。

### 5.3 流程

**导出**

1. `GET /cards/<id>`。
2. `JSON.stringify(card, null, 2) + '\n'`。
3. Blob 下载为 `<id>.dshcd`。
4. 失败（含卡已被外部删除）→ 统一错误提示，不生成空文件。

**导入**

1. 读取文件文本；上限 1 MiB。
2. `JSON.parse`；结果必须是对象。
3. `prepareImport`。
4. `POST /cards`。
5. 409 时用下一个空闲 id 重试一次；仍失败则报错。
6. 成功后清空 file input 的 `value`，刷新列表，提示「已导入为 `<新 id>`」。
7. `versionWarning` 时在提示中说明「版本未验证，已按当前格式导入」。

**复制**

1. `GET /cards/<id>`。
2. `structuredClone`；id 由 `uniqueCardId(`${id}-copy`, ids)` 生成；名称改为
   `<名称> 副本`（名称为空时用新 id）。
3. `POST /cards`；成功后刷新并提示新 id。

**删除**

1. `DELETE /cards/<id>`。
2. 成功后刷新列表，提示「已删除，N 个会话已改为不使用」。

### 5.4 反馈与联动

- 列表上方新增一个 `notice` 状态（`info` / `error`），下一次操作前清空。
- 导入、导出、复制、删除共用这个提示条。
- 列表操作后只刷新设置页；composer 选择器在打开时重新拉取 `/cards`，
  不引入跨组件事件。

## 6. 失败与边界

| 场景 | 行为 |
|---|---|
| 非法 JSON / 非对象 / 超过 1 MiB | 报错，不落盘 |
| `dshcd !== 1` 或缺失 | 警告，继续导入，未知字段保留 |
| id 含大写、空格、非法字符 | 清洗后再导入 |
| 清洗后为空 | 使用 `imported-card` |
| 生成 id 超过 64 字符 | 截断 base，保留后缀 |
| 并发创建导致 409 | 换下一个后缀重试一次 |
| 同一文件连续导入 | 每次清空 input.value |
| 删除不存在的卡 | 404，刷新列表并提示 |
| 删除失败（文件未删） | 500，引用与 live 绑定保持原样 |
| 删除成功但引用清理失败 | 200 + `warnings`，卡片已删；客户端提示清理未完全成功 |
| 导出时卡已被外部删除 | 提示失败，不生成文件 |
| 客户端缺原语 / 宿主不可达 | 沿用现有判空与 try/catch，降级不抛 |

## 7. 验证

### 7.1 离线（`node --test`）

- `uniqueCardId`：空位、后缀递增、64 字符上限。
- `prepareImport`：id 清洗、冲突改名、版本警告、未知字段保留。
- `deleteCardFile`：成功、不存在。
- `detachOverridesForCard`：只改匹配项，其他项不变。
- `clearDefaultCardId`：有指针、无指针。
- DELETE 路由：成功、404、默认指针清理、覆盖表清理、rebind 计数。

### 7.2 活体

1. 新建一张卡 → 导出 → 删除 → 导入 → 字段与未知字段一致。
2. 导入同 id 的卡 → 自动改名为 `-2`。
3. 复制一张正在使用的卡 → 新卡独立，原卡会话不变。
4. 删除正在使用的卡 → 打开该会话 → 下一轮回复不再带角色卡。
5. 删除默认卡 → 设置页显示「未设置」，新会话无卡。

## 8. 风险

- **删除与并发写入**：删除后若另一个请求正好 `PUT`，文件会重新出现。P4 不引入锁；
  以最后一个操作生效为准，并在列表刷新时展示真实状态。
- **live 解绑依赖 `agents` 服务**：服务缺失时只清理持久化引用，live session 保持旧
  绑定直到下一次生命周期事件；不阻塞删除。
- **下载路径在桌面端**：Electron 使用浏览器下载机制；若宿主禁止下载，提示失败而不是
  静默无响应。
