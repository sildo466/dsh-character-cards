# P3 设计 · 卡片编辑器

日期：2026-10-19
上游：`GOAL.md`（D1 格式、D2 影响面、D5 硬规则、D6 未知字段）
前置：P0/P1/P2 已完成（卡片库、注入管线、运行时切卡、设置页、composer chip）

---

## 1. 目标

**在 dsh 设置页里新建、编辑、保存 `.dshcd` 卡片，不用离开 UI、不用手写 JSON。**

### 验收

1. 设置页点「新建卡片」→ 填 `id` 和 `name` → 保存 → 文件出现在 `~/.dsh/character-cards/`
2. 点一张已有卡 → 编辑任意字段 → 保存 → 文件更新，**未知字段不丢**
3. 编辑一张**正在被使用**的卡 → 保存后列表显示「N 个会话正在使用」→ 点「重新应用」→ 那些 session 的提示词当场换成新版本
4. 保存的卡在新建 session 里生效
5. 编辑器的所有控件都是 dsh 自己的形状，**不出现任何 Windows 原生控件**

---

## 2. 范围

**做**

- 新建、编辑、保存
- 字段表单（按 D2 分五组，默认折叠）
- 实时预览：token 估算 + D5 告警
- 「重新应用」到正在使用该卡的 live session

**不做（留给 P4）**

- 导入 / 导出 / 复制 / 删除
- 编辑器以外的卡片生命周期

## 3. 对上游决策的修改

### 3.1 `budget.maxTokens` 不再是格式的一部分

**这条推翻 GOAL D1 与 §8。**

理由：估算方式是 `字符数 ÷ 3`，不是 tokenizer，**用它当硬上限是假精确**；而且实测发现截断是**从尾部**砍的，而渲染顺序把 `constraints` 和优先级声明放在末尾——**超预算时最先消失的是卡片最能生效的部分**。

新的语义：

| 项 | 现在 |
|---|---|
| 渲染 | **永远输出完整卡片，绝不截断** |
| token 数 | **纯信息**，设置页照常显示，没有"超了"这回事 |
| 编辑器的预算校验 | **没有** |

**旧卡里的 `budget` 字段**：变成未知字段，按 D6 原样保留。编辑器**不会**把它抹掉（见 §5.1）。

**代价（明确接受）**：没有任何机制阻止一张巨卡撑爆提示词，只剩可见的 token 数作为信号。

### 3.2 随之删除的代码概念

- `applyBudget()` → 换成 `measure()`：只返回 `{ chars, tokens }`，不做任何裁剪
- `DEFAULT_MAX_TOKENS`、`truncated`、`maxTokens` → 从摘要、状态、诊断里移除
- 预算告警（`over-budget`）→ 不存在

## 4. 宿主

### 4.1 路由

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/cards/<id>` | 卡片的**原始对象** + `sessionsUsing` |
| POST | `/cards/preview` | 草稿 → 校验 + token 估算 + 告警 |
| POST | `/cards` | 新建；`id` 已存在 → **409** |
| PUT | `/cards/<id>` | 更新；文件不存在 → **404**；body 的 `id` 必须与路径一致 |
| POST | `/cards/<id>/apply` | 重新应用到正在使用该卡的 live session，返回 `{ applied }` |

已有的 `GET /cards`（列表）保持不变。

**路由匹配**：`/cards/preview` 注册为 `exact`，`/cards/<id>` 注册为 `prefix`。宿主的 `match()` 先查精确表再查前缀，两者不会打架。

### 4.2 存储与安全

**文件名 = `<id>.dshcd`。** 因此 `id` 必须满足：

```
/^[a-z0-9][a-z0-9-]*$/
长度 ≤ 64
```

不合法 → 预览与保存都返回 400，**不写盘**。这条同时保证：无法路径穿越；P1 用卡自身 `id` 建索引不会与文件名不一致；`default` / `sessions.json` 的引用永远可解析。

**写入用临时文件 + rename**：先写 `<id>.dshcd.tmp`，再 `rename` 到目标。避免写到一半崩溃留下半张卡。

### 4.3 校验与预览

格式规则**只在宿主有一份**——复用 `cards.js` 里现成的 `validateCard` / `renderCard` / `measure`。

**一处必要的小重构**：`validateCard` 现在只通过 logger 报告原因、然后返回 `undefined`，
预览路由需要把原因**交回调用方**。所以拆出一个返回 `{ card } | { error }` 的形式，
`loadCardLibrary` 继续用日志那一版。

```
POST /cards/preview { card }
→ {
    valid: boolean,
    error?: string,
    chars: number,
    tokens: number,
    warnings: Array<{ code: string, message: string }>
  }
```

`warnings` 来自 **D5**（只有两条了）：

| code | 条件 |
|---|---|
| `too-many-rules` | `constraints` 超过 **12** 条 |
| `rule-too-long` | 某条 `constraints` 超过 **60** 字 |

D5 原文的理由："LLM 在任务压力下会忘掉散文式规则"。这两条是**建议**，不阻塞保存。

### 4.4 `sessionsUsing` 与「重新应用」

`GET /cards/<id>` 额外返回 `sessionsUsing`：遍历 `ctx.get('agents').list()`，对每个 agent 用 `resolveCardId` 算它当前生效的卡，等于这张就计入。

`POST /cards/<id>/apply` 对这批 agent 逐个调 P2 已有的 `rebind`——**不新增机制**。

### 4.5 保存不重绑

保存只落盘。已存在的 session 保持它创建时绑定的文本（D4 / D10）。要让它生效必须显式点「重新应用」。

## 5. 客户端

### 5.1 数据流：在原对象上改，不重建

**这是 D6 的落地点。** 编辑器加载到的是**完整原始对象**，`draft` 是它的深拷贝：

```
draft = structuredClone(original)
```

表单只修改它认识的字段，**其他键原样留在 `draft` 里**，保存时整个对象写回。

**绝不允许**从表单字段重建一个 `{ dshcd, id, name, identity, ... }` 新对象——那会在保存一次后抹掉 `budget` 以及将来任何本版本不认识的字段。

### 5.2 视图状态

设置页内部只有两个视图：

```
view = { kind: 'list' }
     | { kind: 'editor', draft: object, original: object | null }
```

`original === null` 即新建。

### 5.3 列表视图

在现有列表上补：

- 顶部 **「新建卡片」**
- 每行可点击 → `GET /cards/<id>` → 进入编辑器
- 行内保留 token 数
- `sessionsUsing > 0` 时显示「N 个会话正在使用 [重新应用]」

### 5.4 编辑器视图

**顶部**：`id`、`name`、`description`。

`id` 新建时可编辑；**创建后只读**（显示为文本，不是输入框）。理由：`id` 是 `default` / `sessions.json` 引用的身份，改名会让引用悬空。

**五个可折叠分组**，用 `DisclosureRow`，每组标题旁带 D2 徽章：

| 组 | 徽章文案 | 依据 |
|---|---|---|
| `identity` 身份 | 低风险 · 影响视角与用词 | D2 |
| `voice` 表达 | **安全** · 只影响表达，不影响正确性 | D2 |
| `code` 代码风格 | **会改变代码** · 影响产出质量与风格 | D2 |
| `workflow` 工作方式 | **高风险** · 影响行为决策 | D2 |
| `constraints` 硬性约束 | 最高优先级 · 逐条遵守 | D1 |

**默认只展开「身份」**，其余折叠。这是"20 个字段不压迫"的实现方式——不是删字段，是不一次全摆出来。

**控件选择**（全部来自 `@deepseek-ai/dsh-client-ui-primitives`）：

| 字段类型 | 控件 |
|---|---|
| 单值文本 | `Input` |
| 数组（`expertise` / `traits` / `avoid` / `constraints`） | 每项一个 `Input` + 添加/删除 `Button` |
| 布尔（`workflow` 三项） | `Pill` 的 `active` 作为开关 |
| 折叠分组 | `DisclosureRow` |
| 动作 | `Button` |

**约束：`Input` 是单行原子控件，dsh 本身没有多行输入原语**（`ui-primitives/src/Input.tsx` 注释明说 composer 的 textarea 属于 conversation 包）。因此**所有标量字段都是单行**，包括 `background` 和 `description`。不引入原生 `<textarea>`。

### 5.5 预览面板

字段变化后 **300ms 防抖**调 `/cards/preview`，显示：

```
152 token  ·  454 字符
⚠ 硬性约束 14 条，建议 ≤ 12
```

预览失败（`valid: false`）→ 显示错误、**禁用保存**，但表单仍可编辑。

### 5.6 未保存的修改

`draft` 与 `original` 深比较得到 `dirty`。

- 脏时「保存」高亮，返回按钮变成 **「放弃修改」**
- 点「放弃修改」进入二次确认（按钮文字变「确认放弃？」），**再点一次**才丢弃
- 不用 `window.confirm`，不引入 modal

### 5.7 保存之后

- 成功 → 回到列表并刷新
- 失败 → 留在编辑器，显示错误，**草稿不丢**

## 6. 失败与边界

| 情况 | 行为 |
|---|---|
| `id` 不合法 | 内联报错，保存禁用 |
| 新建时 `id` 已存在 | 409 + 内联提示 |
| 预览失败（版本号不对、不是对象） | 显示错误、保存禁用、表单仍可编辑 |
| 保存失败 | 留在编辑器，显示错误，不丢草稿 |
| 卡文件被外部删除后保存 | PUT 404 → 提示"该卡已不在磁盘上，保存将重新创建"，二次确认后改用 POST |
| 没有 session 使用该卡 | 不显示「重新应用」 |
| primitives 缺失 | 编辑器显示"控件不可用"，**不回退到原生控件**（用户明确要求） |

**与 composer 切卡控件的差异是刻意的**：那个控件仍保留原生 `<select>` 兜底（P2 已实现）。
编辑器一整屏都是控件，原生外观会让整个页面显得不属于 dsh；而切卡控件只有一行，
且它的 `Menu`/`Pill` 主路径在 0.2.x 上实测可用，兜底从未触发。

## 7. 验证

### 7.1 离线（`node --test`）

- `id` 白名单：合法 / 非法 / 超长 / 路径穿越尝试（`../x`）
- 新建 409、更新 404、body id 与路径不符
- D5 两条告警的边界（12 条 vs 13 条；60 字 vs 61 字）
- **未知字段往返不丢**：加载一个含 `budget` 和其他陌生键的卡 → 经编辑流程 → 写回后仍在
- `measure()` 不再截断：超长文本的 `chars` 等于原长

### 7.2 活体

1. 新建一张卡 → 文件出现在 `~/.dsh/character-cards/`
2. 编辑正在被使用的卡 → 列表显示「N 个会话正在使用」→「重新应用」→ `status` 里对应 session 的 `chars` 变化
3. 新建 session → 新卡生效
4. **编辑器里没有任何 Windows 原生控件**

## 8. 风险

| 风险 | 应对 |
|---|---|
| `DisclosureRow` / `Input` / `Button` 在 0.2.x 里签名不同 | 0.1.3 已有这些原语，且 0.2.x 的原语集更大（`Checkbox` 就是 0.2.x 新增的）。渲染异常时编辑器整体显示"控件不可用"，不拖垮客户端 |
| 未知字段在往返中被抹掉 | §5.1 的"在原对象上改"是硬规则，并有专门测试 |
| `id` 变更导致引用悬空 | 创建后只读 |
| 编辑器把设置页撑爆 | 详情视图 + 分组折叠；列表与编辑器互斥显示 |
| 保存不重绑造成困惑 | 列表明确显示"N 个会话正在使用"和一个显式按钮 |
